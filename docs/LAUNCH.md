# Launch

Drafts, an outreach list, a checklist and an FAQ for the day this repository
goes public. Nothing here is published anywhere yet.

Two rules for everything below.

1. **Every number is checkable.** The figures in these drafts come from
   `demo/site/manifest.json`, from `docs/ARCHITECTURE.md`, and from the
   accuracy table `pytest tests/test_compare.py -k measured -s` prints. If a
   number moves, fix it here before posting; a launch post is the worst place
   to be caught rounding in your own favour.
2. **The limits go in the post, not in the replies.** This project's whole
   argument is that it tells you what it could not do. A launch that hides the
   limits until someone asks has already lost the argument.

## 1. Show HN

**Title**

```
Show HN: Stackroom – turn a folder of FOIA PDFs into a searchable static archive
```

Exactly eighty characters, which is HN's limit, so check it after any edit.
If it reads flat, the alternative is *"Show HN: A static site builder for FOIA
releases that counts the redactions"* (75). Do not use a title that promises a
story; the audience is there for the tool, and a title that oversells is the
first thing a comment will take apart.

**Body**

> `stackroom build ./release -o site` reads a folder of PDFs and writes a
> static website: one real HTML page per page of the documents, full-text
> search, the original files byte for byte, and a ledger of what the agency
> blacked out — how many pages, what share of each page, and which exemption
> they cited where they printed one. No server, no account, nothing uploaded.
> It runs on a laptop and the output is a directory you can drop on GitHub
> Pages or a memory stick.
>
> The bit I'd most like people to poke at: a search result lands on the scan.
> Pagefind returns matches as token positions; the page HTML numbers its tokens
> with the same positions; the word boxes from the text layer or from OCR are
> stored under those same positions. So "match at word 412" becomes a rectangle
> drawn over the ink on the image. That is three parallel sequences that must
> never disagree, which is why one of the six guarantees in the architecture
> doc is "word order in `Page.words` is identical to token order in the page
> HTML" — off by one and every highlight in the archive is on the wrong word.
>
> It also refuses to build a site from a document where a black box covers text
> that is still in the file. The rule is dull — opaque filled rectangle,
> characters at least 80% inside it, painted before the box or in the same
> colour — and the work is all in the exceptions: it has to render the
> rectangle and look at the pixels, because a rectangle in the content stream
> is not necessarily opaque on paper; it has to ignore the string `name
> redacted`, because that is what a common redaction tool prints *under* its
> own box; and it has to leave table rules alone, which is why a rectangle 4pt
> or smaller in either dimension is skipped, and a genuinely thin redaction goes
> with them. Passing
> that check is evidence, not a certificate. `SECURITY.md` lists nine classes
> of thing that get past it.
>
> Limits, before you ask: about 20,000 pages is the ceiling for search it
> stands behind — a reader downloads roughly 202 KB before they can type at
> that size, 122 KB at 5,000 — and past 50,000 it refuses without a flag. A
> redaction applied as an image, a clipping path or a non-rectangular shape is
> invisible to the leak check. A scan skewed by more than about 0.2° defeats
> the visible-redaction detector, so the ledger's percentages get worse while
> the leak check does not. A dark band left by an open scanner lid is genuinely
> indistinguishable from a black box, is counted as one, and says so. PDFs and
> page images only. No LLM anywhere in it.
>
> Demo — an invented city's invented Bureau of Sunlight, 21 pages, generated by
> a script in the repo so you can see exactly what produced every number:
> LINK. Code: LINK. MIT.

**Notes for whoever posts it**

- Post on a weekday morning, US Eastern. Be at the keyboard for three hours
  afterwards; a Show HN with an absent author dies.
- The first comment will be *"why not DocumentCloud"*. Answer it as §6 does —
  DocumentCloud is good, three specific things it cannot do — and never as a
  comparison of quality.
- If somebody says the redaction check makes documents safe, correct them in
  public, immediately, in your own thread. That correction is worth more than
  any upvote.
- Do not post the demo link alone. Half of HN will read only the repo.

## 2. r/foia (and r/journalism)

Different audience: people who *file* requests and get four hundred pages back.
They do not care about token positions. They care about not being locked out,
and about having a number for the first paragraph.

> **I built a thing that turns a FOIA release into a searchable website you host yourself**
>
> Every time I get a response I end up with a stack of PDFs, a folder name with
> a date in it, and no way to let anyone else read them except "here, have a
> 400 MB zip".
>
> This is a command-line tool that takes the folder and writes a website: every
> page gets its own URL with its text on it, search works and lands on the
> right page, the originals stay downloadable, and there is a page that counts
> what was blacked out — how many pages, how much of each, and which exemption
> they cited where they bothered to print it. That last number is usually the
> most quotable thing in a response and nobody hands it to you.
>
> Two things that might matter to this sub specifically:
>
> - **It does not need anybody's permission.** DocumentCloud is good and free,
>   but you have to be verified as a journalism organisation to upload. If you
>   are a requester, a volunteer, a grad student or a community archivist, you
>   are not. This runs on your laptop.
> - **When you win an appeal, it can line the two productions up.** Point it at
>   the 2019 folder and the 2024 folder and it tells you which passages were
>   under a black box then and are readable now, and quotes them. It also does
>   the reverse, which is often the more interesting direction.
>
> It also refuses to publish a document where the black box is only a black box
> and the text is still in the file — run `stackroom check` on documents you are
> about to *send*, not just ones you are about to publish. It is not a
> guarantee. It catches one specific failure and the docs list what it misses.
>
> Free, MIT, no account, no upload. Demo (a completely made-up agency, so the
> screenshots don't involve anyone real): LINK. Code: LINK.
>
> What I actually want from this post: a real release that it reads wrongly.
> That is the most useful bug report there is and I have none from anybody
> else's documents yet.

For **r/journalism**, cut the appeal paragraph down and lead with the ledger:
that sub wants "what would I put in the story", not "what would I file".

## 4. GIJN

GIJN's readers are outside the United States as often as in it, and the things
that matter to them are the ones a US-centric pitch skips: no upload to an
American service, works with no connection, and more than one statute.

> Stackroom is a free, open-source command-line tool that turns a folder of
> released documents into a static website: one page per page, full-text
> search that lands on the scan, the original files, and a ledger counting what
> was withheld and under which article of which law.
>
> Three things that may matter to reporters working outside the US or in
> difficult places. Nothing is uploaded: the tool runs on the reporter's own
> machine and produces a directory of files, so no third party learns which
> documents are being prepared or when. The published archive makes no
> third-party requests at all — no fonts, no CDN, no analytics — so reading it
> does not create a log of who read what, and it works offline from a memory
> stick. And it reads statutory withholding codes for four jurisdictions — US
> FOIA and the Privacy Act, the UK Freedom of Information Act 2000, Canada's
> Access to Information Act, and EU Regulation 1049/2001 — with the interface
> available in English, Polish, Russian and Ukrainian. Adding a jurisdiction is
> a dictionary of code numbers and plain-language glosses; adding a language is
> one catalogue file, with a checker that tells you what is still missing.
>
> It also compares two productions of the same records and says what one
> release withheld and the next did not, which is the ordinary shape of an
> appeal in most countries that have an access law.
>
> The documentation is unusually blunt about what the tool cannot do, and that
> is deliberate: the chapter on comparing two releases spends more space on how
> a finding can be wrong than on how the diff is computed, and every caveat in
> it is also printed on the published page, beside the finding it weakens.
>
> Demo: LINK · Code: LINK · MIT licence.

Send it to the GIJN Toolbox address rather than to an individual editor, and
say plainly that you are the author.

## 6. Outreach

Specific people and organisations, and why each one. **Check current
affiliations before you write** — people move, and a mail addressed to
somebody's last job is a mail that gets deleted. Write to individuals only
where you have something specific to say to them; otherwise write to the
project.

### The three adjacent document platforms

Tell these three *first*, and before the public launch, so they hear it from
you rather than from a thread. Frame it as complementary, because it is: they
all do things Stackroom does not.

- **DocumentCloud**, now stewarded by MuckRock. The tool everyone will compare
  this to. The honest pitch: Stackroom is for people DocumentCloud's
  verification requirement excludes, and for archives that must outlive an
  organisation's funding. It is not a competitor for a newsroom that already
  has an account.
- **Aleph** (OCCRP). Server-based, entity extraction, cross-document search
  across leaks. Friedrich Lindenberg's work is the reference implementation for
  this whole category. Stackroom is what you publish *after* you have used
  something like Aleph to work out what you have.
- **Datashare** (ICIJ). Local-first, indexes documents on the journalist's own
  machine — the closest philosophical relative here. Datashare is the reading
  tool, Stackroom is the publishing tool; the two want a bridge, and someone at
  ICIJ will see that immediately.

### FOIA and access-to-information organisations

- **MuckRock** — their users are exactly the requesters who cannot upload to
  DocumentCloud. Michael Morisy co-founded it and has written for years about
  what happens to documents after they arrive.
- **mySociety / WhatDoTheyKnow** (UK) — they host an enormous archive of
  authority responses and have had to deal, publicly and painfully, with
  authorities disclosing more than they meant to in attachments. The
  failed-redaction check is directly relevant to their moderation queue, and
  they already ship a UK FOI vocabulary in their own head.
- **FragDenStaat** (Open Knowledge Foundation Deutschland) — publish released
  documents at scale, fight about them in court, and would want a German
  exemption vocabulary. Arne Semsrott is the obvious person and a German
  vocabulary is an afternoon for someone who knows the IFG.
- **Access Info Europe** (Madrid) — Regulation 1049/2001 is already in the
  tree; they are the people who would know whether the glosses are right.
- **The National Security Archive** (George Washington University) — the
  `compare` feature exists because of the thing they do: requesting the same
  records repeatedly over decades and putting the productions side by side.
  Show them the comparison page and nothing else.
- **Reporters Committee for Freedom of the Press** — the FOIA Wiki is where
  US requesters look things up; a tool entry there reaches them for years.
- **OGIS**, the US Office of Government Information Services — a long shot,
  but they convene the FOIA Advisory Committee and the ledger is an argument
  about processing quality that the committee actually debates.
- **Right To Know** (OpenAustralia) and **Ma Dada** (France) — the same shape
  of organisation as WhatDoTheyKnow, and each is one vocabulary away.

### Newsrooms with document desks

- **ProPublica's news apps team** — they publish document sets as part of
  stories and have written repeatedly about doing it well.
- **The Documenters network** (City Bureau) — trained community members
  covering public meetings, producing records nobody else publishes. They are
  the "locked out" audience made literal, and their output is exactly the size
  Stackroom handles well.
- **Bellingcat** — publishes source document sets alongside investigations and
  cares about readers being able to verify.
- **The Intercept**, and any newsroom that has published a document release
  with a "read the documents" page — that page is what this replaces.
- **Local and regional data desks** — the Chicago Tribune, the Texas Tribune,
  the BBC Shared Data Unit and their equivalents. A newsroom with one data
  reporter and no infrastructure budget is the sweet spot.

### Archives, libraries and preservation

- **The Internet Archive** — a Stackroom site is a self-contained directory of
  static files with a manifest of SHA-256 digests. That is close to an ideal
  object to mirror, and worth saying to them in those words.
- **Webrecorder** (Ilya Kreymer) — WACZ and ReplayWeb.page come from the same
  instinct: self-contained, static, no server, verifiable. A conversation about
  packaging a Stackroom archive as a WACZ would interest both sides.
- **The Library Innovation Lab at Harvard** (Perma.cc, and their data
  preservation work) — same instinct again, plus institutional weight.
- **Documenting the Now** — their whole subject is the ethics of archiving
  material about people who did not choose to be archived. They will have
  sharp, useful criticism of the redaction ledger, and it is worth hearing.
- **The Society of American Archivists' Electronic Records Section** — where
  the people who will have to keep these archives alive in ten years are.

### Maintainers of tools this is built on or beside

Say thank you, say what you used it for, and do not ask for anything.

- **Pagefind** (CloudCannon; Liam Bigelow). Stackroom leans on a Pagefind
  feature — token positions in results — in a way its authors may not have
  seen before. They collect unusual uses.
- **pdfplumber** (Jeremy Singer-Vine). The library the whole ingest rests on.
  He also writes *Data Is Plural*, which is read by precisely the audience for
  this, so this is one mail with two reasons.
- **OCRmyPDF** (James R. Barlow). Adjacent problem, and his writing on PDF text
  layers is the clearest there is. A note on how the invisible-render-mode case
  is handled here would be a real conversation.
- **Datasette** (Simon Willison). Different data, same politics: local-first,
  static output, publish-anywhere. He writes up tools like this, and his
  audience overlaps with HN's without being the same people.
- **Tabula** — the other tool journalists reach for when handed a PDF.

### Places rather than people

- **NICAR-L**, and a lightning talk or demo at the next NICAR conference.
- **Source** (OpenNews) — they publish build-notes from newsroom tool authors,
  and the redaction-detection write-up is exactly their length and register.
- **Hacks/Hackers** chapters, and the News Nerdery Slack.
- **r/foia**, **r/journalism**, **r/datasets**.
- **Hacker News**, **lobste.rs**.
- **Data Is Plural**, if the demo archive is interesting enough to be a dataset
  in its own right — it is not, so this is really the pdfplumber mail.

A rule for all of it: **do not blast**. Six good mails that name a specific
thing the recipient has done beat sixty that begin "Dear team".

## 7. Launch checklist

### Before anything is posted

Everything here is a blocker, not a nice-to-have.

- [ ] `pytest` green, **including the browser suite** — it skips silently
      without a built demo site, so build `demo/` first and check it ran.
- [ ] `ruff check` and `mypy` clean.
- [ ] CI green on the whole support matrix, on a fresh clone.
- [ ] **`<SECURITY-CONTACT>` replaced** in `SECURITY.md`, with an address
      somebody actually reads, and GitHub's *Private vulnerability reporting*
      switched on in Settings → Code security. Both, not one.
- [ ] **`<CONDUCT-CONTACT>` replaced** in `CODE_OF_CONDUCT.md`, and it must not
      be the same person as the security contact if it can be avoided.
- [ ] The response times promised in `SECURITY.md` are ones you can keep this
      month. Lengthen them now rather than miss them later.
- [ ] `LICENSE` present, and the bundled font licences shipped with the wheel.
- [ ] Version tagged, `CHANGELOG.md` topped, release built and **installed from
      PyPI on a clean machine** — `pipx install "stackroom[search]"` — not just
      from the working tree.
- [ ] `stackroom doctor` gives correct instructions on a clean macOS and a
      clean Ubuntu, including the Tesseract language packs.
- [ ] The demo is built and hosted at a URL that will not move, with `base_url`
      set in its config, and the search index working on the real host.
- [ ] Every number visible in `docs/images/*.png` re-checked against
      `demo/site/manifest.json`. Rebuild the demo, retake the shots, or fix the
      alt text — but do not post a screenshot you have not re-verified.
- [ ] Every relative link in `README.md` resolves in the GitHub renderer.
- [ ] Nothing in the list of rough edges below has come back, and anything new
      found since is written down in a public issue, so nobody has to discover
      it in a thread.
- [ ] Somebody has agreed to be at a keyboard for the first three hours, and
      somebody has agreed to watch the security inbox for a week.

### Rough edges found while building the demo

Five, all found by building `demo/` and running the suite against it, and all
five since fixed. They are kept here because each is a trap that can be walked
back into, and because a launch is a bad time to rediscover one. Check the list
against the tree before posting rather than trusting this paragraph.

1. **The withheld ledger overflowed sideways on a phone at the largest text
   step**, which the project's own browser suite caught:
   `tests/test_qol_browser.py::test_text_size_changes_and_nothing_overflows_at_the_largest_step`
   failed against this demo (`withheld/index.html`, scrollWidth 500 in a 380px
   viewport). One line of CSS — `.doc__meta .mono { white-space: nowrap }` —
   met a template that emitted a page's whole exemption list as a single
   `.mono` span, and a page citing six codes was a forty-character unbreakable
   run. **Fixed** in the templates rather than the stylesheet, whose intent was
   right: `withheld.html.jinja` and `negative.html.jinja` now emit one span per
   code, and the list breaks between them. `withheld/negative/index.html` had
   the same overflow and is covered too.
2. **The failed-redaction table showed at most three findings per page** while
   the headline counted them all, so a page with four leaks reported five
   passages above four rows with nothing saying a row had been dropped. In the
   one report that must not omit evidence, that was the wrong default.
   **Fixed**: `cli.LEAK_ROWS_PER_PAGE` is the cap, a page with more says *"…
   and N more passage(s) on this page"*, and the table closes with *"that is
   every one of the N passage(s)"* when nothing was left out.
3. **A page in a language not listed in `ocr.languages` was reported as
   unreadable**, even when it was born-digital with a perfect text layer: the
   stopword ratio was computed against the declared languages only, so a
   Russian page in a collection declared `["eng"]` scored zero. **Fixed**:
   `lang.stopword_ratio` takes the maximum over every list it has whatever it
   is told, so a declared language is a prior that can only raise a page's
   score. See the changelog entry, which explains why there is no second
   "expected languages" setting.
4. **White lettering reversed out of a large black box read as a failed
   redaction.** An exemption code printed inside a page-sized rectangle is a
   common real layout, and the pixel-flatness test passed because the lettering
   was a tiny share of a big box. **Fixed**: the check asks each character
   about *its own* footprint, where a white stem beside a black counter is the
   most textured thing on the page, and the box-level flatness answer now
   speaks only for cells too small to measure. `demo/build-demo.py` draws the
   page withheld in full the way an agency really does — the heading reversed
   out of the box — and `stackroom check` stays quiet on it.
5. **A margin stamp was not attributed to a mid-line redaction.** Codes
   attached to a box within about 40pt, which a stamp in the left margin
   exceeds for any redaction that is not at the start of a line, and the ledger
   reported the commonest layout in FOIA releases as "withheld under something;
   the page does not say what". **Fixed**: a code is read onto the box on its
   own *line* at any distance across the page, then onto a box beside it, then
   onto nothing — and a line with several boxes and no near code stays
   ambiguous rather than being guessed at. `demo/build-demo.py --stamp
   {margin,in-box,auto}` builds the demo either way, which is how the
   difference is measured rather than argued about.

### The first 48 hours

- **Stagger the channels.** Hacker News first, alone. lobste.rs the next
  morning. NICAR-L and GIJN a day after that, once you know which questions
  come up. Reddit last. Posting everywhere at once means answering everywhere
  at once and doing all of it badly.
- **Answer everything in the first three hours**, then hourly. A dead Show HN
  thread is a dead launch.
- **Say "I don't know" out loud.** The audience being courted here can smell a
  hedge from a long way off, and the project's entire pitch is that it admits
  things.
- **Never let "it passed the check" stand as "it is safe."** If a commenter
  says it, correct it in the same thread within the hour. This is the one
  thing worth being repetitive about.
- **A report of a missed leak goes private immediately.** Reply once, in
  public, with a link to `SECURITY.md` and nothing else. Do not discuss the
  document. Do not ask for it in the thread.
- **Expect the first three issues to be installation.** poppler and Tesseract
  on macOS, a missing language pack, and `pipx` not putting the binary on
  `PATH`. Have the answers written before you post.
- **Ask, once per channel, for a real release that breaks it.** That is the
  only thing this project cannot generate for itself.
- **Keep a list of every question asked twice.** That list is the next version
  of §8, and it is worth more than the traffic.
- **Ship a patch release within 48 hours** for the first genuine bug somebody
  finds. Fixing something in public on day one buys more trust than a clean
  launch does.
- **Do not argue about DocumentCloud.** One answer, from §8, then move on.

## 8. FAQ, answered honestly

These are the questions that will come, with the answers as they should be
given: short, specific, and conceding the point where the point is good.

### Why not DocumentCloud?

Use DocumentCloud if it fits you. It is good, it is free, it has a real
organisation behind it, and it does things this does not — annotation, sharing
with collaborators, an API, a public corpus other reporters can find your
documents in.

Three things it cannot do:

1. **Let you in.** Uploading requires verification as a journalism
   organisation. A FOIA requester, a court-watch volunteer, a graduate student
   and a community archivist are all outside that door.
2. **Let you keep it.** A Stackroom archive is your files in a folder. Anyone
   can mirror it, fork it or re-host it without asking anyone, and it does not
   stop existing when somebody's grant does.
3. **Count the redactions.** Nothing free does this. It is what turns a place
   to put documents into the thing that produced the number in your first
   paragraph.

If you have a DocumentCloud account and no reason to leave, keep it.

### Why not a server? Wouldn't a real backend be better?

For most of what a server would buy you, yes. Collaboration, access control,
incremental upload, cross-collection search — all easier with a database.

The reason not to is that an archive with a server has an operator, and an
operator is a single point of failure, a hosting bill, a maintenance burden,
and a log of who read what. Static output means the archive can be mirrored by
someone who has never heard of this project, read from a memory stick in a
room with no connection, and kept alive in ten years by anyone who can serve a
directory. That is the trade, and it is the right one for documents whose whole
value is that they can be checked later by someone you will never meet.

### How big can it get?

Search is the constraint, not the page count. A reader downloads about 122 KB
before they can type at 5,000 pages and about 202 KB at 20,000; 20,000 pages is
the size this stands behind. Between 20,000 and 50,000 it works and degrades,
and the build tells you what it will cost. Past 50,000 it refuses to write the
site unless you pass `--i-know`.

Two things people get wrong about this. Query time tracks the *number of hits*,
not the size of the archive — a two-letter query that matches everything is slow
in a small archive too, which is why very short queries are refused. And the two ceilings are
different things: `--no-search` silences the warning above 20,000, because that
warning is about the index — but the refusal above 50,000 lives in the CLI and
still wants `--i-know`. Every page is a real HTML file either way, so a very
large collection is publishable without a search box at all; a search engine or
`grep` can still read it.

### Is the redaction check safe to rely on?

**No. It is evidence, not a certificate.**

What it tells you is that one specific failure — text still present under an
opaque rectangle, on a page it could read — is not in the files you gave it.
That is the failure that has burned people, so it is worth checking, and the
build stops rather than publishing when it finds one.

What gets past it, in full, is in `SECURITY.md`. The short version: a redaction
applied as an image, a clipping path or any non-rectangular shape; a rectangle
4pt or thinner in either dimension; a redaction sitting entirely in the top
43pt of the page; text hidden by something other than a box over it; and
anything in the file that is not page content — metadata, XMP, attachments,
annotations, and the earlier revisions an incremental save leaves behind, all
of which are published with the original file.

If somebody's safety depends on a document, a machine's opinion is not the last
step. It is one step, and this one is honest about being one.

### What about documents that aren't in English?

Recognition is Tesseract's, so anything Tesseract can read, this can read: name
the language packs in `ocr.languages`. Pages with a real text layer — most
born-digital PDFs — are read directly and never go near the recogniser, so a
page in a script you have no OCR data for still works if the text layer is good.

The interface ships in English, Polish, Russian and Ukrainian, and a fifth
language is one catalogue file with a checker that lists what is still missing.
Statutory exemption glosses stay in English on purpose, because a
mistranslation of a legal term is worse than an untranslated one. No
right-to-left catalogue ships, because the stylesheet is not finished for it,
and saying otherwise would waste somebody's afternoon.

`ocr.languages` is the list handed to the recogniser and nothing else. It used
to double as the list of languages the quality judge expected, which labelled a
perfectly good born-digital page in an undeclared language unreadable; the judge
now scores a page as whatever language it is, and a page in a script no word
list covers is reported as unjudged rather than as garbage.

### Does it use AI?

No. There is no model in it, no API key, and nothing that phones anywhere. OCR
is Tesseract, which is a recogniser rather than a generator; everything else is
geometry, string matching and arithmetic on rectangles.

That is a deliberate choice, not an oversight. The reason to publish documents
this way is so a reader can check what an archive claims against the page it
claims it about. A summary that is confidently wrong about a document is worse
than no summary, because it is quotable. Where recognition fails, this says
where it failed, and where a percentage is uncertain, it says why.

### Can I use it for leaked documents?

Be careful, and read `docs/THREAT-MODEL.md` first.

The tool runs locally and uploads nothing, which is the property you want. But
it publishes the original file byte for byte unless you turn on
`safety.strip_metadata`, and an original PDF carries far more than its pages:
document metadata, XMP, attachments, form fields, and the earlier revisions an
incremental save left behind. It also writes rendered page images into a cache
on the machine it runs on, and `stackroom check` rasterises every page into a
temporary folder — whose path it prints, which it deletes, and which
`--scratch` will put on a ramdisk.

None of that is a substitute for knowing where a document came from and who
touched it. The tool cannot tell you that.

### Who is behind this? Will it still exist in a year?

Answer this one plainly and do not oversell it. If it is one person working
evenings, say so. The honest version of the pitch is that the *output* does not
depend on the project's survival: a built archive is static files with a
manifest, it has no runtime dependency on anything here, and it keeps working
if this repository is abandoned tomorrow. That is a better answer than a
promise about maintenance, and it happens to be true.

### Why Python? It'll be slow.

It is, in the places where it matters least. The heavy work is in subprocesses
that are not Python — `pdftoppm` renders, Tesseract recognises, and the search
index is built by the `pagefind` binary rather than its Python bindings, which
are about sixty times slower for identical output. What is left is I/O and
arithmetic over rectangles, and the page cache means the second build of a
collection is seconds rather than hours.

Python is also the reason the exemption vocabularies are a dictionary anybody
can extend, and that matters more here than throughput.

### Is the output accessible?

Every page is a real HTML document with its text in it, readable with
JavaScript off, so a screen reader gets the transcription without waiting for
anything. The scan itself is marked decorative — empty `alt`, and the highlight
overlay `aria-hidden` — because the transcription beside it is the same content
in text, and reading a page number twice is worse than not reading a picture.
The redaction ledger is a table rather than a picture, and the negative, which
really is a picture, is one object to a screen reader with the same pages and
the same figures listed underneath it in text.

It is not audited, and nobody should claim it is. If you find something that
does not work with your reader, that is a bug and a public issue is the right
place for it.

### Can I run it in CI, or on a schedule?

Yes, and the build is deterministic if you pin the date: set
`SOURCE_DATE_EPOCH` and two builds of the same folder are byte-identical, which
means a reader can rebuild your archive from your documents and diff it against
yours. Publish the value you used. Without it, the only differences are the
build stamp in `manifest.json` and the date in the page footers.

### Something in my release is wrong in the archive. Is that a security bug?

Almost certainly not, and a public issue is the right place. OCR errors, a
missed redaction *count*, a wrong withheld percentage, a mis-parsed exemption
code — all ordinary bugs, all welcome.

The one thing to report privately is a document where a black box covers text
the check did not find. Do not attach it, do not paste the recovered text, and
quote it only as its shape — `#####, ########`, which is the form the tool
prints for exactly this reason. `SECURITY.md` has the procedure.
